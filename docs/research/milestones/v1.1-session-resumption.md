# v1.1: bonded SMP L4 plus ML-KEM application resumption

**IMPLEMENTED / SOFTWARE VALIDATED — HARDWARE VALIDATION PENDING.**

v1.1 extends frozen v1.0. BLE authenticated LE Secure Connections L4 remains
mandatory, with a 16-byte link key and the existing Numeric Comparison/bonding
ceremony. Full application authentication uses ML-KEM alone for its PRK and
the CP3 transcript/FINISHED chain. No SMP DHKey or LTK is mixed into K_RESUME.
The application data plane retains CP4 framing, AAD, derived nonce construction,
exact-next sequences and two 16-byte challenge/echo rounds, 51 bytes per frame.
Its explicit wire version and domain are v1.1.

After the authenticated full FINISHED_P send/verification commit, a separate
RAM-only application ticket can resume within 24 hours and 100 successful uses.
A successful bonded resume restores BLE L4 and then runs the four symmetric
resume frames, with fresh session ID/nonces/traffic keys. It skips ML-KEM and
does not run a new Numeric Comparison ceremony. The BLE bond alone is
insufficient to resume the application session; DK reboot retains BLE settings
but loses the RAM ticket, so the application performs full ML-KEM fallback.

The application ticket binds to `bt_conn_get_dst()` (resolved LE identity in the
installed NCS v3.0.0) as address type plus six bytes. Identity shape and an actual
matching default-local-identity bond are required. Resume additionally requires
the bond to have existed at connect. Real registered bond-deletion and new-pairing
callbacks invalidate the application ticket; loss of L4 aborts application state.
The [design audit](../session-resumption-design.md) records the SDK source paths.
