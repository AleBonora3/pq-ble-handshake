# Milestone v0.3 — ML-KEM-768 BLE End-to-End

## Result

End-to-end ML-KEM-768 key establishment was successfully validated
between a PC Central and a Nordic nRF54L15 DK over real BLE/GATT.

Central:
- Python
- liboqs / ML-KEM-768

Peripheral:
- nRF54L15 DK
- Cortex-M33
- mlkem-native v2.0.0 portable C

## Real BLE flow

1. Peripheral generates an ML-KEM-768 keypair on-device.
2. Central reads the 1184-byte public key using GATT long reads.
3. Central performs ML-KEM-768 encapsulation using liboqs.
4. The 1088-byte ciphertext is transferred over GATT in five
   application fragments.
5. The nRF54L15 reassembles the ciphertext.
6. A dedicated crypto worker performs mlkem-native decapsulation.
7. Central and Peripheral derive the same 32-byte shared secret.
8. Equality is verified using a TEST-ONLY CRC-32 diagnostic.

## Security note

The CRC-32 shared-secret comparison is TEST ONLY.

It is:
- not authentication;
- not a KDF;
- not cryptographic key confirmation;
- not part of the final protocol.

The shared secret itself is never transmitted over BLE.

## Current limitations

- deterministic TEST-ONLY ML-KEM KeyGen coins;
- no production hardware RNG yet;
- no HKDF on the DK;
- no AES-GCM on the DK;
- no ECDH/hybrid handshake yet;
- no cryptographic key confirmation yet.
